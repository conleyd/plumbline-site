Security

Security design

This page describes what Plumbline is built to do. It describes the design, not an audited result.

No certification yetNo SOC 2 report or other security certification has been issued for Plumbline. Nothing on this site should be read as a claim of one.

Per-company encryption

  • Each company has its own data key. The key is created with AWS Key Management Service, stored only in wrapped form, and bound to the company's ID, so it cannot be used to decrypt another company's data.
  • Connector credentials, financial amounts, work email addresses, uploaded files and evidence files are encrypted with AES-256-GCM under that key. Each encrypted value is bound to its company, field and row, so it cannot be copied elsewhere and still decrypt.
  • Data keys rotate every year, and on demand after an incident.
  • The database, backups and file storage are also encrypted at rest with separate AWS-managed keys. Traffic is encrypted in transit with TLS 1.2 or later.

Company isolation

  • Each company's rows are separated in the database by row-level security, behind a company-scoped data layer and tests that check every table is covered.
  • Sponsor accounts cannot read portfolio company tables at all. They read separate aggregate tables, and only while a data agreement is in force.
  • No figure covering fewer than five people is shown to anyone other than the person it describes, and rules stop small groups being recovered by subtracting one total from another.
  • Roles are enforced in the data layer, not only by hiding things in the interface.

Read-only connectors

Every connector requests the narrowest read scope the vendor offers. A test fails if any connector calls a write method that its definition does not declare. The design allows only four kinds of write, each limited as shown:

  • Plumbline's own package objects in a Salesforce org that installs the optional package (configuration, license state and OAuth linkage only).
  • Direct messages in Slack or Microsoft Teams. There is no method for posting to channels.
  • Opt-in task mirroring into one project the company's admin chooses. Off by default.
  • Publishing an approved pack or answer to a data room, with a named approver for each publish.

Agents never handle passwords. Every sign-in is OAuth, an app install, or a key that a person at the company pastes in. See Integrations and data use for each source's scopes.

Evidence storage

  • Evidence and audit records are append-only. The application can add and read them, but not change or delete them.
  • Each company's records form a SHA-256 hash chain, which is recomputed every night; a mismatch pages the on-call engineer.
  • Evidence files are kept in storage with object lock, retained for seven years unless the company closes its account.
  • AI output is a proposal until a named person approves it. No AI tool can write data without that approval.

Individuals

  • The content of AI prompts and chats is never collected. Incoming usage data is checked against an allowlist of counts and metadata, and unknown fields are dropped.
  • There are no leaderboards and no ranked lists of people.
  • Every read of raw financials or one person's data is logged, and the company's admin can see that log.

Closing an account

When a company exports and closes its account, Plumbline revokes its sessions and connector credentials, deletes its live data, and destroys its data keys, which leaves its encrypted evidence files unreadable. Backups holding its data expire by day 28. A deletion certificate is issued on day 30.
